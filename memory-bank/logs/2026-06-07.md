## Session 4 — console-log triage: offsetWidth crash, Scene#background v14 migration, onClick deprecation

Shane shared a fresh `console-logs-latest.txt` from a live run and asked to fix
the issues in it. **The run itself fully succeeded** — the Calcified Leviathan
scene generated, built (46 walls, 3 doors, 7 lights, 7 journals), AND drew on
canvas (62 assets). Three things to clean up; all fixed (working-tree only).

### 1. `offsetWidth` crash — `GeneratorApp` (vibe-scene-two `scripts/ui/generator-app.js`)
`Uncaught TypeError: Cannot read properties of null (reading 'offsetWidth')` at
`_updatePosition`. Root cause: with `position: { height: "auto" }`, Foundry runs
`setPosition()` → `_updatePosition()` every render, reading
`el.parentElement.offsetWidth`. The app's `close()`-then-`render({force:true})`
reopen pattern (after the ProgressDialog finishes in `_onNextStep`/`_onFinish`)
renders while the element isn't re-attached → `parentElement` null. **Fix:**
override `_updatePosition` to bail when `!this.element?.isConnected`.

### 2. `Scene#background` deprecation — `scene-builder.js` (resolves the Session-3 thread)
The deprecation warning came only from the **read** `scene.background?.src` in
the background safety-net (deprecated v14, removed v16). Migrated read →
`scene.firstLevel?.background?.src` and the re-apply update →
`scene.update({ levels: [{ _id: firstLevel.id, background: { src } }] })`.
- **Key Session-3 finding:** in v14 the scene background lives on a **Level**,
  not `Scene#background`. `Scene.create({ background: { src } })` is auto-migrated
  into a default level by `Scene#_preCreate` (no warning), but post-create
  reads/updates must use `scene.firstLevel`. The Level's `background.src` is a
  `virtual: true` `FilePathField` — likely why the persisted doc kept showing
  `background.src: null` in the LevelDB log even when the image was set.
- **The Session-3 symptom did NOT reproduce here.** Today's log shows the
  safety-net warn still firing (`background.src missing after create; re-applying`)
  and then the background rendering fine — so the net works; my change just makes
  the re-apply forward-compatible (the old `"background.src"` update key is itself
  a v14→v16 shim). Net effect: scene background appearing is now working in the
  desktop app. (Consistent with the Session-3 lead that Shane likely hadn't
  reloaded the client when the first attempt "didn't work.")

### 3. `SceneControlTool#onClick` deprecation — `module.js` (vibe-scene-two)
The generator scene-control tool defined both `onClick` (deprecated, removed V15)
and `onChange`. In V14 Foundry fires `onChange` but routes the lingering `onClick`
through `#onChange` and warns. **Fix:** removed `onClick`, kept `onChange`, and
switched `render(true)` → `render({ force: true })` (V1 boolean is invalid in V2).
Swept the suite: vibe-common `vibe-menu-injector.js` already uses `onChange`;
vibe-actor's `onClick`s are `getHeaderControlsApplicationV2` controls, which
*correctly* use `onClick`. vibe-scene-two was the only offender.
